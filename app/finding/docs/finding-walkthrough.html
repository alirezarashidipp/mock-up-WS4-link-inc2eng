Finding candidate engagements

One supplier can deliver several services. Finding uses the supplier name on an incident to retrieve engagement records for the next stage to assess.

  1. Select supplier incidents

    Read CLASSIFIED_INCIDENTS.csv. Select rows whose class is exactly SUPPLIER. Skip blank supplier names and the whole value Unknown, ignoring surrounding whitespace and case in the name check.

    Example incident name   The Azure-Solutions (Ltd.)

  2. Clean the incident name

    Lowercase the text, delete periods, treat ampersands as and and replace configured separators such as hyphens and parentheses with spaces. Keep digits.

    Remove whole words in the stop-word list, such as the and solutions, and legal terms such as ltd and inc. A selected incident with an empty search name is recorded as INVALID_NAME in the results CSV.

    The Azure-Solutions (Ltd.) → the azure solutions ltd → azure

  3. Apply a whole-name YAML alias

    Finding reads config/supplier_aliases.yml with PyYAML. When the entire cleaned name matches an entry, it uses the replacement as the search name. This lets supplier exceptions be maintained in one file.

    YAML entry   azure: Microsoft
    Search name   microsoft

  4. Compare the configured engagement fields

    Read ENG_ALL.csv. Clean each available field listed in engagement.search_columns_eng and compare it with the incident search name. Each matching field supplies its strongest result to deduplication.

    microsoft against Microsoft → EXACT
    Against Microsoft UK Ltd → SUBSTRING

    For a search name of one to four characters after alias replacement and space removal, a substring must match a whole word. For example, ICE matches ICE Data Services and skips Office Supplies.

  5. Recover spelling errors with fuzzy matching

    The Python library fuzzy-match==0.0.1 provides Levenshtein similarity. It scores how many character insertions, deletions or substitutions separate two names, relative to the longer name. This gives a repeatable way to catch typos.

    For a search name of at least 5 characters, Finding compares it with adjacent whole words in the engagement field. A score of 0.72 or higher qualifies.

    Microsfot against cleaned Microsoft Ltd → two edits in nine letters → 0.778 · FUZZY

    A lower threshold catches more typos but can also admit unrelated suppliers with similar names. A higher threshold can miss genuine spelling variants.

  6. Save all Finding results

    engagement_candidates.csv contains one MATCHED row per incident and matching engagement ID. The strongest method wins, with the first source record winning a tie. A selected incident with zero candidates gets one row with empty engagement fields. Its status is NO_MATCH for a usable name or INVALID_NAME for an empty search name.

    If one incident matches three engagements and another matches none, the CSV has four rows. Linking assesses the three matched rows.
